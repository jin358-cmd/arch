# 新建建築專案工作流程

單頁式建築專案管理工具，整合甘特圖、看板、日曆、列表、工期與預算方案、施工協作廠商、核定審查、檢核與會議紀錄。

## 雲端自動同步

本版本已整合 Supabase：

- 使用電子郵件與密碼登入；同一帳號可在不同筆電同步。
- 專案仍會先保存在瀏覽器，離線時可繼續編輯，恢復連線後自動補送。
- 專案名稱與每一組工作資料分開做版本比對，避免整份專案互相覆寫。
- 偵測到兩台裝置同時修改同一資料時，雲端版本會套回原案，本機工作資料另存為「同步衝突備份」；原案的雲端附件仍保留在原案，已有本機快取的附件會一併複製到備份。
- 會議附件存放於私人 Storage bucket，每個檔案上限 20 MB，並保留本機離線快取。
- 頁首雲端列會顯示：確認中、僅本機、待同步、同步中、已同步、離線、衝突或錯誤。

公開網站（部署後）：[https://jin358-cmd.github.io/arch/](https://jin358-cmd.github.io/arch/)

## 另一台筆電使用方式

1. 開啟公開網站。
2. 按「登入同步」。首次使用按「建立帳號」，到信箱完成確認。
3. 在另一台筆電以相同電子郵件與密碼登入。
4. 雲端專案會自動加入專案下拉選單；後續修改約在數秒內同步。

請以 HTTPS 公開網站使用登入與跨裝置同步。直接開啟 `file://` 版本仍可離線編輯，但不建議作為正式登入入口。

## 主要檔案

- `index.html`：完整工作流程與雲端同步介面。
- `supabase-config.js`：Supabase URL 與瀏覽器可公開的 publishable key。
- `supabase-sync.js`：登入、離線佇列、版本衝突、Realtime 與附件同步。
- `supabase/migrations/`：資料表、RLS、私人附件 bucket 與 Realtime 設定。
- `supabase/SETUP.md`：Supabase 後台與部署檢查說明。

## 安全設計

前端只含 `sb_publishable_...` 公開金鑰；它不是管理密鑰。所有專案表均啟用 RLS 與使用者隔離，未登入的 API 請求無法讀取專案資料。請勿把 `service_role`、secret key、資料庫密碼或 SMTP 密碼加入此儲存庫。
